# 验证器校准（初步）：用现有基线数据算「预测可行 × 实测超期」

日期：2026-10-28
数据来源：`pr10e_baseline/baseline.json`（PR-10E 阶段 A，4 条件 × 10 轮 × 5000 拍，周期 1000 µs，CPU3 亲和）
对应评审问题：「还需要验证模型误差、误拒绝率，以及**是否有预测通过但实际超期**的情况。」

本文只回答最后那个问题，且**不新跑任何实验**——用已经采集的 10 轮数据即可判定。

---

## 一、验证器当时给了什么判定

该配置（`mixed_pid_stateful.c`，1000 µs 周期/期限）在流水线里被验证器判为**可行**：
`ecos_from_c` 正常产出 `plan.json` 与 driver（PR-10B v2 的 `partial_kernel_p1000`、
`user_only_p1000` 两个格子都有产物），即 `verification.ok = true`，没有被 `[DEADLINE]` 或
`E_WINDOW*` 拦下。

验证器的模型只含：阶段执行时间 + 窗口/顺序约束 + 跨域/同步边界成本。**不含调度延迟。**

## 二、实测结果（同一配置，两组调度类各 10 轮）

| 部署 | 调度类 | 逐轮超期次数 | 有超期的轮数 | 合计超期 /5 万拍 | resp max 中位 |
|---|---|---|---|---|---|
| 全用户态 | CFS | 3,0,2,0,0,0,1,1,1,6 | **6 / 10** | 14 | **1037.0 µs** |
| 全用户态 | FIFO 99 | 全 0 | 0 / 10 | 0 | 45.7 µs |
| 部分内核化 | CFS | 0,9,1,0,1,2,1,3,1,1 | **8 / 10** | 19 | **1741.2 µs** |
| 部分内核化 | FIFO 99 | 全 0 | 0 / 10 | 0 | 56.4 µs |

注意 resp max 中位：CFS 下 **1037 / 1741 µs**，都**大于 1000 µs 的周期本身**——
最坏那一拍照样把整拍预算吃光，不是"稍晚一点"。

## 三、混淆矩阵

把「验证器预测可行」当作阳性预测，「实测任一轮出现超期」当作实际的不可行：

| | 实测**不**超期 | 实测超期 |
|---|---|---|
| **预测 pass** | **真阴 20 轮**（两个部署 × FIFO 各 10 轮） | **假阳 14 轮**（CFS：6 + 8 轮） |
| 预测 reject | 未测（见第五节） | 未测 |

也就是说：**在默认 CFS 下，验证器的「可行」判定有 14/20 轮被实测推翻。**
换到 FIFO 99，同两个部署 20 轮全部零超期，判定的可信度立刻成立。

## 四、这说明什么（以及不说明什么）

**说明**：验证器的适用边界比"能不能过"这个字面含义窄。它建模的是
「计算 + 边界」这条链，**没有把调度延迟纳入模型**；而在 CFS 下调度延迟（被抢占后重新获得 CPU）
的量级是 **毫秒级**，远大于它建模的那几微秒。

所以在 CFS 下，"verification.ok = true" **不能**被读作"该部署能满足 1 ms 硬实时"。
这正好印证评审那句：验证器目前只能叫**"基于模型的可行性筛选器"**，不能宣称硬实时可调度性。

**不说明**：这不是"验证器写错了"。它的输入里本来就没有调度类这个变量，
从没声称覆盖调度延迟。问题在于**使用时的解读**——如果把它当"实时性背书"，就会错。
本文的价值是把这条边界用实测数字划出来，而不是指责模型。

**一个直接的设计推论**：既然同一份程序在 CFS 与 FIFO 下的超期从 14/20 轮变成 0/20 轮，
「调度配置」就不是环境细节，而是**部署决策的自变量**。编译器的候选空间应该是

```
CFS 用户态 → FIFO 用户态 → 部分内核化 → 内核自主执行
```

而不是二元的「用户态 / 内核态」（评审已指出这一点，此处补上超期率的实证）。

## 五、明确未测的：误拒率（假阴）

**测不出**，原因是架构性的：被 `reject` 的方案不生成产物（fail-closed 的代价），
没有 driver 就没有实测，无法判断"拒绝的那个方案本来会不会超期"。

要测必须给流水线加「强制生成」开关，那会破坏 fail-closed 语义（产物可能在验证不通过时被 make 出来），
本阶段不擅自加。`scripts/pr10e_calib__验证器校准.py` 里对应项写作 `not_measured`，不填估值。

**唯一的间接证据**（PR-10B v2 的 400 µs 格）：验证器拒绝的是"部分内核化"（预测 426 > 400），
而**同周期下"全用户态"被放行且实测 0 超期**。这说明该次拒绝挑掉的是更慢的那个方案，
很可能是**正确拒绝**而非误拒——但这是单点佐证，不是误拒率的估计。
