## 0. 怎么在没有 cmake 的板子上编插件

Pi 上没装 cmake/ninja，但插件可以直编（3 个 .cpp，不需要链 LLVM 库）：

```bash
cd /root/K-Fusion/kfusion
clang++-16 -shared -fPIC -O2 -fno-rtti $(llvm-config-16 --cxxflags) \
  -I backend/pass -I include \
  -o /tmp/KFusionPass_new.so \
  backend/pass/PLCFusionPass__内核化Pass.cpp \
  backend/pass/PLCFusionFixedPoint__定点Pass.cpp \
  backend/pass/KFusionWCETSchedulePass__函数级WCET.cpp
# → 零错误，194 520 字节
```

## 1. P1-1：定点 Pass 把 `sext` 改成 `zext`

**用例**：`kfusion/backend/test/sext_negative.ll`（纯整数，无浮点）

| 实现 | `@sext_keep` 产物 | 判定 |
|---|---|---|
| 旧 `build16/KFusionPass.so` | `%0 = zext i32 %x to i64` | ❌ 复现审查结论（−1 → 4294967295） |
| 新 `/tmp/KFusionPass_new.so` | `%0 = sext i32 %x to i64` | ✅ `$FC` 通过 |

**改法**：`adjustIntWidth()` 增加显式 `SignedExt` 参数；修复既有 `CastInst` 时传
`castIsSignedExt(C)`（沿用原 opcode）；`fixMul/fixDiv/intToFixed/AShr` 支路显式传 `true`。

## 2. P1-2：NuttX 线程桩写回 8 字节，覆盖相邻字段

**类型核实**（仓库内预处理文件 `kfusion/test/nuttx_target/cyclictest_nuttx.i`）：
```c
typedef int pid_t;          // L174
typedef pid_t pthread_t;    // L332  → 4 字节
```

**改法**：桩签名改为 `pthread_t *` + 直写调用者存储；返回值改为 POSIX 语义（不再读 `errno`）。

**反汇编验证**（同一份等价 C，`-O2 -mcpu=cortex-a53`）：

```
<old_create>:  str x2, [x1]     ← 8 字节写
<new_create>:  str w2, [x1]     ← 4 字节写 ✅
```

**编译验证**：真实桩文件用 NuttX 头编译通过
（`aarch64-none-elf-gcc -c … -I nuttx/include -I apps/include -D__NuttX__ -mcpu=cortex-a53 -Os -fno-builtin -ffreestanding`，rc=0，3 472 字节）。

> 未做：整镜像 `make` 重链（会替换当前用于测量的 `nuttx.bin`，留到换镜像时做）。

## 3. P1-3：间接调用直接化，丢条件分支

**用例**：`indirect_select_branch.ll`
```llvm
%fn = select i1 %use_free, ptr @free, ptr @release_device
call void %fn(ptr %p)
```

| 实现 | 产物 | 判定 |
|---|---|---|
| 旧版 | `call void @plc_kfree(ptr %p)`（select 仍在但已被绕过） | ❌ 条件为假也会 free |
| 新版 | 保留 `select` + `call void %fn(ptr %p)` | ✅ |
| 新版（同目标双分支 `select cond, @free, @free`） | `call void @plc_kfree(ptr %p)` | ✅ 未矫枉过正 |

**改法**：`resolveIndirectCalleeImpl()` 的 `select / phi / 实参回溯` 改为**唯一目标才返回**；
实参回溯额外要求该参数的**所有**使用者都是对本函数的调用，否则返回"不可证"。

## 4. P1-4：未映射调用默认被删除并返回成功

**策略**：`PLC_FUSION_UNMAPPED_POLICY = error(默认) | keep | blackhole`
（旧开关 `PLC_FUSION_BLACKHOLE=1` 仍兼容，但会打印醒目警告）。

| 场景 | 旧版 | 新版（error） |
|---|---|---|
| `unmapped_strict.ll`（`device_write`） | rc=0，调用被删，调用者返回 0 | **rc=1**，逐条列出 `device_write (caller: apply_device)` |

### 4.1 在真实产物上抓到的真问题：`fwrite`

NuttX 版 cyclictest（1115 行，同一份 `.i`）跑 `plc-kernelize-mainline`
（`PLC_FUSION_ROOTS=main`）：

| 实现 | `main` | `call @fwrite` | 未映射警告 |
|---|---|---|---|
| 旧版 | 1 | **0 ← 写直方图的调用被删除** | 2 |
| 新版（`fwrite` 进 kKeep 前） | — | — | 构建直接失败（这正是期望行为） |
| 新版（`fwrite` 进 kKeep 后） | 1 | **2** | 0 |

→ `fwrite` 一直不在白名单，产物静默丢失了"写直方图"这段。已补进 `isPreservedExternal()`。
这条就是审查所说"符号审计只能看到剩下的引用，发现不了已经被删除的操作"的实例。

### 4.2 产物级验证（llc + ld -r + nm）

```
llc-16 -mtriple=aarch64-none-elf -mattr=+fp-armv8,+neon -O2 -filetype=obj  → fused.o (20 968 B)
ld -r fused.o stubs.o → combined.o (23 224 B)
nm -u combined.o | grep -c ' U plc_'  →  0        # 所有 plc_* 都被桩解析
```
剩余未定义符号全是 NuttX libc 该提供的（`fwrite / malloc / pthread_create / clock_gettime …`），
其中 `pthread_create` 来自桩自身对真实 API 的调用，符合分层预期。

## 5. 测试门禁：16/16

修了 3 个**与 pass 行为无关**的过时断言（审查也点到了）：

| 用例 | 问题 | 修法 |
|---|---|---|
| `remap_malloc.ll` | 期望 `call i8* @plc_kmalloc`，LLVM16+ 输出 `ptr` | `call {{.*}}@plc_kmalloc` |
| `remap_pthread_create.ll` | CHECK 顺序反了（`worker` 定义在调用之前） | 先 `CHECK: define @worker` 再 `CHECK: call` |
| `indirect_store_alloca.ll` | `store void ()* @fp_target`（typed pointer） | `store {{.*}}@fp_target` |

结果：**16 / 16 通过**（含 3 条新用例）。

> ⚠️ 复现坑：从 Windows 打包上传的 `.ll` 带 CRLF，`grep '^; PASS:'` 会把 `\r` 吃进 `-passes=`，
> opt 报错但 stdout 为空，FileCheck 只报 `'<stdin>' is empty`。上传后必须 `sed -i 's/\r$//'`。
