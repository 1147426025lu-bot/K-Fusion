# 替代方案（Plan B）：把论文做成"可复现的归因研究"，而不是"大而全的框架"

> 2026-10-21
> 背景：`THESIS_MAINLINE` 定的是主线，本文回答"如果要冲会议，最可能过的那版长什么样"

---

## 0. 先定评判标准：这个方向什么样的论文能过？

系统/编译会议（RTAS / LCTES / EMSOFT）对这类工作的三个必问：

1. **你的编译器做了什么别人做不到的事？**
2. **你的数字可信吗？（会不会是测量装置自己造成的？）**
3. **换一个负载/平台还成立吗？**

"我们更快"几乎必然被第 1 条挡回来——因为底噪由 OS 决定，编译器动不了。
能过的形态通常是下面两种之一：

- **A 型（机制型）**：提出一个变换，并证明它有非平凡的性质（可判定、保持语义、可组合）；
- **B 型（方法论型）**：提出一种测量/归因方法，并用它得出**反直觉但可复现**的结论。

我们手上最硬的是 B 型材料（三域归因、自扰消融、偏置反证、符号审计），
A 型材料偏弱（重映射 + 定点化 + DCE，单独看不构成新变换）。

**所以 Plan B 的定位：以 B 型为主干，用一个小的 A 型机制（依赖闭包）做支撑。**

---

## 1. 一句话

> **同一份未经修改的 POSIX 控制程序，经编译期内核化后，其 OS 依赖面会收缩为一个
> 可静态审计的极小闭包；正是这个闭包让"同一份产物跨三个运行域部署"成为可能，
> 从而第一次把实时性改善**干净地分解**到隔离层、架构层与编译器层。**

关键词：**可审计闭包 → 同产物跨域 → 受控归因**。

---

## 2. 四个贡献（每条都有现存证据或明确缺口）

| | 贡献 | 现状 | 缺口 |
|---|---|---|---|
| **C1** | **依赖闭包的可计算性**：编译期输出"该程序需要哪些 OS 原语"，并证明它跨负载稳定 | 机制已有（重映射 + DCE），闭包可 `nm -u` 直接读出：cyclictest 在 NuttX 上从 **27 个 POSIX → 17 个 `plc_` + 5 个 libc** | 只测了 1 个负载，需 2–3 个负载的闭包统计表 |
| **C2** | **同产物三域归因**：268 µs → 7.834 µs（**34×**，隔离层）→ 4.9 µs（**1.6×**，架构层） | 数据齐全（20 min / 120 万样本 / resync=2） | A 域 268 µs 需同口径复测 |
| **C3** | **测量方法学**：自扰消融（>3 µs 事件 328→2）、偏置反证（2529 ns 被 EWMA 吸收，均值仍 0.1 ns）、会话级基线（min 4.796/4.889/5.204/5.259）、符号级审计（17 处 null + 1 处静默删除） | 全部完成 | 无 |
| **C4** | **诚实的负结果**：内核化对抖动**中性**（A 4.937 vs C 4.926 µs，差 0.2%，三轮复现）；`plc_` 层 258 ns/次可消除；FixedPoint 使产物**可链接**（去掉软浮点运行库依赖） | 全部完成 | 无 |

> C4 是这套方案的关键：**主动报告"我们的机制没有让抖动变小"**，
> 反而让 C2 的归因更可信——因为我们没有动机把功劳往自己身上揽。

## 3. 为什么这个版本更可能过（预答三条质疑）

**Q1：编译器做了什么？**
→ 把一个程序的 OS 依赖面收缩成可审计闭包，使它能在**不重写**的前提下跨域部署。
这不是"优化"，是**可移植性原语**；而可移植性正是归因实验的前提。

**Q2：数字可信吗？**
→ C3 的四件工具就是答案，且每一件都给出"关掉之后数字会怎样"的对照
（自扰消融 328→2、偏置注入被吸收、跨会话基线漂移 6–10%）。

**Q3：换个负载还成立吗？**
→ C1 的闭包表 + C2 的三域矩阵本身就是"跨负载/跨域"的答案；
再补 BM2 一个真实控制律，就有第二组数据点。

## 5. 与 Golden Thread 方案对比

| | Golden Thread | Plan B |
|---|---|---|
| 定位 | A 型（机制型，6 个支柱） | **B 型（方法论型）+ 小 A 型机制** |
| 需要新建的能力 | outlining、SCEV、乒乓注入、OpenAMP | 基本无（只补负载与统计） |
| 现有数据利用率 | 约 40% | **约 85%** |
| 失败模式 | 任一支柱做不出来，整篇崩 | 单点失败只损失一段 |
| 审稿人可能说 | "每一样都 70%" | "机制偏薄，但归因扎实、数据诚实" |

## 7. 风险与兜底

| 风险 | 概率 | 兜底 |
|---|---|---|
| "依赖闭包"被判为已有工作（unikernel / library OS 的按需链接） | 中 | 不主张闭包本身新，只主张**"闭包 → 跨域 → 归因"这条链**；把闭包降为实现手段 |
| FixedPoint 在 PID 上溢出 | 中 | 加饱和与范围检查，并把"Q32 的动态范围边界"写成一条可量化的限制（这本身是个结果） |
| A 域 268 µs 复现不到 | 低 | 改用"关闭隔离栈"的对照实验，如实报告差异 |
| 审稿人认为"结论是负结果，不够 novel" | 中 | C2 的分解本身是正结果：34× 与 1.6× 的归属此前无人给出 |

---

## 8. 一句话总结

**Golden Thread 想让论文"看起来什么都做了"；Plan B 让论文"只做一件，但让审稿人无法反驳"。**
后者在系统会议上通常更容易过，而且我们 85% 的材料已经躺在仓库里了。
