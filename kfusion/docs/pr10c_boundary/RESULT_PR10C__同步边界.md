# PR-10C：同步边界到底吃掉多少（空 ioctl 地板价）

日期：2026-10-28　机器：Pi4（内核 5.15.86 aarch64）　脚本：`scripts/pr10c_boundary__边界拆解.py`

## 要回答的问题

PR-10B v2 观测到：部分内核化的中位时延比全用户态稳定高 4–5 µs。
但 4–5 µs 里有多少是**同步边界**（陷入/锁/copy/唤醒），有多少是**内核计算**？
不拆开，任何"内核化不划算"的归因都只是猜。

## 做法

造一个**什么都不算**的内核模块：消息结构与真实 UKU 完全一致（同一个
`kfusion_uku.h`），ioctl 里只做 `copy_from_user` → 校验 → 互斥 → 时间戳 →
`copy_to_user`，**不调用任何阶段函数**。再用同构的微基准每拍发一次 ioctl。
这就是同步路径的地板价，且因为计算为 0，地板价本身就是边界成本。

## 结果（每条件 3 轮 × 5000 拍）

| 对象 | 往返 min | 往返 **avg** | p99 | max |
|---|---|---|---|---|
| 空 ioctl（无计算） | 2.35–2.43 µs | **2.74–2.79 µs** | 5–6 µs | 8.8–23.0 µs |
| mixed（真实部署，无负载） | 2.50 µs | **3.10 µs** | 8 µs | 14.6 µs |
| mixed（真实部署，4 忙循环） | 4.02 µs | **9.73 µs** | 199 µs | 2417 µs |

同一次 mixed 运行里，内核侧计算时间：`min=0.129 avg=0.164 max=0.870 µs`。

## 拆解

- 往返 avg 3.10 µs − 内核计算 avg 0.164 µs ≈ **2.94 µs 是同步边界**
- 空模块地板 2.74–2.79 µs ⇒ **边界项基本全部来自协议本身，而不是计算**
- 计算占往返的比例：0.164 / 3.10 ≈ **5.3%**
- 也就是说：**95% 的往返时间花在"把活交给内核再拿回来"这件事上。**

加压后更明显：往返 avg 从 3.10 涨到 9.73 µs（p99 199 µs），而内核计算只从
0.164 涨到 0.224 µs。**负载放大的是边界，不是计算。**

## 结论

1. **4–5 µs 的中位差主要就是同步边界**，与"内核里算得慢"无关。这个负载的计算
   只有 0.16 µs，无论放哪都快。
2. 因此优化方向不是"让内核算得更快"，而是**减少跨界次数或消除跨界**：
   批量提交（一拍一次变多拍一次）、共享内存 + 内核自主周期执行、或干脆留用户态。
3. 这也解释了 PR-10B v2 的尾部现象：`ioctl` 路径在争抢下会被调度/锁拖到百微秒
   甚至毫秒（p99 199 µs、max 2417 µs），而用户态自旋循环没有这条路径。

## 诚实边界

- **探针分桶是 1 µs**，所以 `p50` 只能取到整数（2 或 5）。本文用 `avg` 与 `min`
  做亚微秒级判断，不用 p50 的差值当精度。
- 空模块**没有阶段调用**，比真实部署少几个函数调用与一次写回；但同步路径
  （陷入、互斥、两次 copy、两次时间戳）完全相同——这正是要隔离的变量。
  空模块地板 2.77 vs 真实 3.10 的 0.33 µs 差，就含这部分。
- 单机、每次 3 轮，不报显著性；这是量级拆解，不是统计推断。
- **尚未做「内核自主周期执行」对照组**（消除每拍 ioctl 的部署）：那是 PR-10C 第二步，
  也是判断"内核执行本身"优劣的必要条件。本文只说边界贵，没说内核执行慢。

## 对论文的意义

这把"内核化在这个负载上不划算"从**观测**推进到**机制**：
不是内核代码慢，而是**握手贵**。因此论文的部署决策必须把
`C_boundary`（跨界成本）当成一等公民——这也正是评审建议的目标函数
`J(d) = αQ₉₉ + βR_miss + γC_boundary` 里第三项的实测依据。
