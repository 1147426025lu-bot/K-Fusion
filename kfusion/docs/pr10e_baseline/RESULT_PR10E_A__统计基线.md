# PR-10E 阶段 A：冻结内核的统计基线（10 轮 × 5000 拍）

日期：2026-10-28　机器：Pi4（内核 5.15.86 aarch64，周期 1000 µs）
脚本：`scripts/pr10e_baseline__统计基线.py`　CPU 亲和：CPU3（`taskset -c 3`）

## 设计（按评审要求）

- **不改内核、不开 tracing**：这一阶段只补统计。
- **同一份驱动比两种部署**：只构建一份 UKU 产物，`user_only` 跑 `gold`（全用户态）、
  `partial_kernel` 跑 `mixed`（中间组走 ioctl）。**两者是同一个二进制**，
  唯一差异是中间组是否跨域——比的是部署，不是两份代码。
- 每种部署 × {CFS, FIFO 99} 各 **10 轮独立重复**，每轮 5000 拍，逐拍原始样本落盘
  `runs_*/rNN.csv`（`k,start_lat_ns,exec_ns,resp_ns`）。
- 逐轮从**原始样本**重算分位数，再跨轮给中位数与极差。

## 三个结论

**1. 「12.41 → 23.30 µs」的轮间波动不是 p50 的波动。**
用 p50 看，四格的跨轮极差只有 **0.28–0.46 µs**。上一次看到的 12.41 vs 23.30 是 **avg**：
少数异常拍会把均值拉高（本轮 avg 逐轮也在 12.16–13.18 之间抖，CFS 更明显：62.98–67.56）。

> **方法论教训：报均值会制造假波动。** 论文里的数字必须用 p50/p99 + 极差，
> 并且明确写"报的是哪个统计量"。

**2. 调度类的影响是压倒性的，部署之间的差别很小。**
- p50：CFS 62.7–63.1 µs vs FIFO 11.9–12.3 µs（**5.3×**）
- 超期：CFS 14–19 次 / 5 万拍，FIFO **0 次**
- 同等调度下，两种部署的 p50 只差 **0.45 µs**（12.32 vs 11.87），
  response max 差 10.8 µs（56.4 vs 45.7）——方向依旧不利于部分内核化。

**3. 尾部（p99 / max）仍然是轮间波动的主战场，且 CFS 更不稳。**
p99 跨轮极差 12–45 µs，CFS 的 response max 中位到 **1.0–1.7 ms**，FIFO 压到 46–56 µs。

## 诚实边界

- 单机、单 CPU 亲和（CPU3）、单源码；10 轮是重复，但不是跨机器/跨天重复。
- **FIFO 99 会饿死其他任务**：5 秒窗口可接受，不代表可长期这样跑。
- 超期判定用 1000 µs 期限；`exec` 列未在此表列出（见 csv）。
- 全部实测，**不是 WCET**；max 是观测值，不构成上界。
- 未做任何机制归因：ms 级尖峰来自 IRQ / 调度 / 锁竞争**仍然未知**，这正是阶段 B–D 的目的。
