# IVSHMEM 跨域共享内存通道（NuttX inmate ↔ root cell Linux）

> 目的：打通 **Jailhouse 分区内 NuttX 实时域** 与 **root cell Linux** 的共享内存通信。
> 这是 cRTOS「remote syscall」机制的地基（原论文靠它让实时域复用 Linux 功能）。
> 状态：**2026-10-16 已实测双向打通**（见 §5）。

---

## 1. 前提（均已具备）

| 项 | 值 |
|---|---|
| 板子 | Raspberry Pi 4B |
| hypervisor | Jailhouse v0.12-342-gd6e64f90，root cell `Raspberry-Pi4` 占 CPU0/2/3 |
| 实时域 | `rpi4-nuttx` cell，CPU1，NuttX（tickless） |
| root 侧驱动 | `uio_ivshmem`（**内建**，非模块），PCI 设备 `0001:00:00.0 [110a:4106]` |
| 设备节点 | `/dev/uio0` |
| cell 侧声明 | `configs/arm64/rpi4-nuttx.c` 的 `mem_regions`（ROOTSHARED）+ `.pci_devices`（`shmem_dev_id=1, peers=3`） |

## 2. 共享区布局（root 侧 `/sys/class/uio/uio0/maps`）

| map | 名称 | 物理地址 | 大小 |
|---|---|---|---|
| map0 | registers | 0xffa00000 | 4 KiB |
| map1 | state_table | 0x1faf0000 | 4 KiB |
| **map2** | **rw_section** | **0x1faf1000** | **36 KiB（3 peer × 3 KiB）** |
| map3 | input_sections | 0x1fafa000 | 24 KiB |
| map4 | output_section | 0x1fafa000 | 8 KiB |

- root 侧：`mmap("/dev/uio0", len, offset = map_index × 4096)`。
- inmate 侧：cell 已把同一物理地址映射到**相同 guest 虚拟地址** `0x1faf1000`。
- ⚠ 本 PoC 直接用 `rw_section` 的起始 16 字节做 mailbox，**未**实现 Jailhouse 内置协议的
  peer 分片约定（每 peer 3 KiB）；做正式协议时应按 `shmem_dev_id` 分片。

## 3. 自定协议（mailbox，32 位字，两端一致）

| 偏移 | 名称 | 谁写 | 含义 |
|---|---|---|---|
| 0x00 | `ROOT_MAGIC` | root | 证明 root → inmate |
| 0x04 | `INMATE_SEQ` | inmate | 每轮 +1，证明 inmate → root |
| 0x08 | `INMATE_ECHO` | inmate | 回写最近读到的 magic，证明 inmate 读到 root |
| 0x0C | `INMATE_STATE` | inmate | 1 = running |

## 4. 实现要点（踩坑记录）

1. **inmate 无需改 MMU**：NuttX 的 `DRAM0_S0 = [0, 0xFC000000)` 以 `MT_NORMAL` 映射，
   **0x1faf0000 已在页表内**，可直接读写。
2. **cache 必须自己维护**：NuttX 侧是 cacheable，root 侧（UIO mmap）通常非 cache →
   inmate 读前 `up_invalidate_dcache(base,end)`、写后 `up_clean_dcache(base,end)`，
   否则互相看不见。（函数在 `arch/arm64/src/common/arm64_cache.c`；
   `include/nuttx/arch.h` **没有**声明，app 里需自行 `extern`。）
3. **初始化值**：cell 刚创建时 rw_section 全 `0xFFFFFFFF`（未初始化）。
4. **构建接入**：NuttX 的 `apps/examples/Kconfig` 是 **autogenerated**，新增 app 必须手动
   加一行 `source ".../examples/xshm/Kconfig"`；`build_nuttx_inmate__*.sh` 的
   「3b. 注入 overlay apps」已自动完成（含幂等）。
5. **inmate 日志用 ASCII**：中文经 `printf` 到串口会乱码，嵌入式日志一律 ASCII。

## 5. 实测验证（2026-10-16）

```
# [A] 部署 cell 后，root 侧基线（未初始化）
ROOT_MAGIC=0xFFFFFFFF  INMATE_SEQ=4294967295  INMATE_ECHO=0xFFFFFFFF  INMATE_STATE=4294967295

# [B] root 写入 magic
$ python3 ivshmem_probe.py poke
已向 /dev/uio0 map2 off 0x00 写入 ROOT_MAGIC = 0xA5A5C0DE

# [C] inmate(串口 NSH) 运行 —— 读到 root 写的值
nsh> xshm -i 20 -n 600
xshm START base=0x1faf1000 interval=20ms iters=600
xshm: ROOT_MAGIC -> 0xa5a5c0de (iter 0)
xshm DONE seq=600 last_magic=0xa5a5c0de got_root_magic=1

# [D] root 读回 inmate 写的数据
ROOT_MAGIC=0xA5A5C0DE  INMATE_SEQ=600  INMATE_ECHO=0xA5A5C0DE  INMATE_STATE=1
raw: A5A5C0DE 00000258 A5A5C0DE 00000001 FFFFFFFF FFFFFFFF
```

- **root → inmate**：inmate `got_root_magic=1`，读到 `0xA5A5C0DE` ✅
- **inmate → root**：root 读到 `INMATE_SEQ=600`（0x258）、`INMATE_ECHO=0xA5A5C0DE` ✅

## 6. 用法

```bash
# 1) 部署 cell（Pi，root）
CELL_BIN=/root/kfusion-pi4/out/rpi4-nuttx.cell \
  bash /root/kfusion-pi4/scripts/deploy_nuttx_cell__部署NuttX_cell.sh

# 2) root 侧：写 magic / 持续监视
python3 /root/kfusion-pi4/scripts/pi4/ivshmem_probe.py poke
python3 /root/kfusion-pi4/scripts/pi4/ivshmem_probe.py watch

# 3) inmate 侧（串口 NSH）
nsh> xshm -i 20 -n 600      # 10ms/20ms 周期跑 600 轮
```
