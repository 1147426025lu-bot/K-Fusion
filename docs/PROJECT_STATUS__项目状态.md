# K-Fusion 项目状态与证据边界

更新日期：2026-10-28。本文区分“已进入主线的实现”“已有经验验证”和“仍属于研究目标”的内容。

## 当前主张

K-Fusion 的核心对象是 **语义—时间约束下的选择性内核化**：编译器不预设全内核化，而是对阶段的部署域、融合分组、通信和时间安排做联合选择；任何候选都必须满足状态版本、顺序、时间窗口、域能力和保留义务。

## 主线实现状态

| 环节 | 当前实现 | 证据性质 |
|---|---|---|
| Gate 0：基线冻结 | 记录版本、平台与短测条件 | 可复核记录 |
| Gate 1：阶段提取 | 周期入口、直接阶段、全局状态、读写集合；非法入口结构 fail-closed | 单测 + Pi 端到端 |
| Gate 2：TEIR/版本依赖 | 同拍数据边、跨拍输入、状态版本与时间事实 | 单测 + 示例验证 |
| Gate 3：独立复核 | plan、生成代码、事件语义检查与反例拒绝 | 独立工具 + 反例 |
| Gate 4：候选选择 | 域、融合/通信、窗口、版本硬约束；STKP v1 小规模穷举 + 剪枝 | 自测 + 五阶段示例 |
| Gate 5：代码生成/运行 | Linux 用户态、Linux 内核态及实验性跨域生成 | 构建/板上短测 |
| Gate 6：消融与反例 | always-kernel、always-LET、非法版本/窗口/域等反例 | 自动脚本 + 报告 |

## 已实现与未证明的分界

### 已实现

- Clang/LLVM 路径提取阶段和全局状态读写。
- K-C0 禁止调用与未知副作用的保守拒绝。
- TEIR 和状态版本依赖。
- 二元部署/融合等候选决策的枚举、剪枝、成本排序。
- 计划与生成物的独立检查。
- 五阶段闭环、无状态流水线和反例集合。

### 不应据此宣称

- 对任意 C 程序的完整语义等价。
- 完整指针别名、并发、递归或动态内存证明。
- 采样最大时间等同于 WCET。
- 五阶段示例选出的 B/D 方案对其他平台或成本输入仍然最优。
- 当前穷举器适合大规模工业程序；v1 的定位是小规模独立 oracle 和研究验证。

## 五阶段示例如何解读

Sample–FIR–PID–Clamp–Plant 的部署结果由示例契约、域能力、阶段成本、通信成本和时间窗口共同决定。仓库现有短测中，某组成本令用户态融合 B 胜出；降低内核成本时可翻转为内核态 D；加入链式时间窗口时全融合会被拒绝。它证明的是“选择能随假设变化且约束会生效”，不是某一阶段天然必须内核化。

## 证据等级

| 等级 | 含义 |
|---|---|
| 静态/单元验证 | 检查编码规则与反例，不能替代板上执行 |
| 生成物验证 | 检查输出结构、计划与事件关系，不等于通用等价证明 |
| 板上短测 | 指定条件下可运行和经验性能，不能称 WCET |
| 长测/压力测 | 增强经验可信度，仍需要明确环境与统计方法 |
| 形式化证明 | 当前仓库未提供通用 WCET 或通用 C 等价证明 |
