## 0. 三十秒版

> 别人问"你的方案比 cRTOS 快多少"，正确的回答是：
> **"不比。我比的是谁能说清改善来自哪一层。"**
>
> 我们让同一份编译器产物跨越 **Linux 内核态 → NuttX 分区 → （未来）裸机** 三个运行域，
> 于是 268 µs → 7.8 µs → 4.9 µs 这条曲线可以被拆成三段独立归因：
> 隔离层 **34×**、架构层 **1.6×**、编译器层 **≈0**（有实验证明这个 0 是本质的，不是实现不足）。
> 今天又拆出第四层：root cell 上那恒定 20 µs 里有 **9 µs 是 hypervisor 的确定性开销**。

卖点是 **归因（attribution）**，不是 **跑分（score）**。

## 1. 这个课题在赌什么

### 1.1 问题定义：一个真实的度量困境

实时性工程已经有三条成熟路线，而且都能把抖动压到 µs 级：

| 路线 | 代表 | 典型底噪 |
|---|---|---|
| 内核抢占改造 | PREEMPT_RT | 数十 µs |
| CPU/中断隔离 + 抢占抑制 | isolcpus / cgroup / IRQ affinity | **7–8 µs** |
| hypervisor 硬分区 | Jailhouse / cRTOS（Access'25） | **~5 µs** |

与此同时，编译器能做的优化（更少指令、更少访存、定点化）量级是 **几十到几百 ns**。

> **100 ns 的收益，淹没在 5000 ns 的 OS 噪声里 → 根本测不出来。**

这不是 K-Fusion 一家的困境，是 **"编译器 × 实时系统"整个交叉领域的困境**：
大家都能说"更快"，但说不清"快的是哪一层"。

### 1.2 我们的赌注

不是造一个更快的调度器/分区器（那条路已经被 cRTOS 走到 ~5 µs，收益递减），
而是 **让被测物本身变得可搬运**：

> 如果**同一份机器码**能在三个域里跑，那么三个域之间的差值就**只能**归因于运行域。
> 单变量控制不是靠"尽量配平参数"，而是靠"物理上就是同一个二进制"。

这一步把"归因"从修辞问题变成实验问题。

## 2. 机制：编译期内核化到底做了什么

K-Fusion pass（`PLCFusionPass__内核化Pass.cpp` + `PLCLowJitterPass`）在 **LLVM IR 层**做三件事：

| # | 动作 | 目的 | 失败时的表现（都是实测踩过的） |
|---|---|---|---|
| 1 | **符号重映射**：`malloc/open/clock_gettime/pthread_*` → `plc_*` 抽象层 | 切断对 OS 运行时的直接依赖，改由后端桩提供 | 未映射的外部符号被**黑洞化**（`load ptr, ptr null`）→ data abort |
| 2 | **定点化（Q32）** | 消除软浮点运行库依赖 | `llvm.fmuladd` 未处理 → IR 非法；循环携带 PHI 支配关系违规 |
| 3 | **IR 层埋测量点** | 测量不再依赖外部工具（cyclictest 之类） | —— |

**ABI 层**：`plc_*` 共 17 个符号（`plc_ktime_get_ts`、`plc_nanosleep`、`plc_printf`…），
两套后端桩分别实现：Linux 内核模块版、NuttX 版（`plc_runtime_stubs__NuttX桩.c`）。

**工程证据（E1）**：同一份 **1115 行** NuttX `cyclictest.c`、同一个 pass、两套桩，
分别产出 **Linux 内核模块** 与 **NuttX 可执行体**——这不是"移植"，是"同一产物两种落地面"。

> 措辞纪律：**禁用 "kernel fusion"**（被 TVM/XLA/MLIR 强占用），统一写
> *compiler kernelization* / *task kernel synthesis*。

## 3. 实验设计的总原则（四条，比单个实验更重要）

这四条是整篇论文的"方法论骨架"。审稿人真正会看的是这四条，不是某个数字。

### P1 — 单变量靠"同一份产物"，不靠"配平参数"

- 比编译器层：**同一个 gcc/clang、同一个优化档，唯一变量 = 过不过 pass**。
- 比运行域：**同一个二进制、同一个核、同一个优先级、同一个周期，唯一变量 = 运行域**。
- 比 hypervisor：**同一个二进制、同一块板，唯一变量 = `jailhouse enable/disable`**（今天做的）。

> 反面教材（已撤回）：曾用 `--hot main` 让 pass 给整个 `main` 加 `optnone`，
> 测出"pass 慢 18%"，其实那是冻结整个函数的代价 → 后来用 T1/T2 独立函数对照重做。

### P2 — 每个主张配一个"证明自己没作弊"的反证

| 反证 | 针对的质疑 | 做法 | 结果 |
|---|---|---|---|
| **自扰消融** | "你的测量工具自己就是噪声源" | 监控器 `ps` 扫描 → 看门狗 debugfs → SD 卡回写，逐级关闭 | >3 µs 事件 **328 → 2** |
| **偏置反证** | "指标是不是可以靠调参刷低" | 人为注入 2529 ns 偏置 | 被 EWMA 闭环完全吸收，稳态均值仍 0.1 ns |
| **符号级审计** | "产物是不是偷偷调了 OS" | 融合产物每个外部符号必须能追溯到目标平台实现 | 抓出 17 处黑洞化 + 1 处被静默删除的 `pthread_setschedparam` |

前两项证明 **测量没有自我干扰**，第三项证明 **产物没有自我欺骗**。

### P3 — 每条结论都写清口径（这是最容易被拒的地方）

1. **极值不可跨窗口比**：1 h 的 760 µs ≠ 15 min 的 96 µs ≠ 100 s 的 48 µs。
2. **绝对延迟不可跨会话比**：NuttX 的 min 在 4.796 / 4.889 / 5.204 / 5.259 之间跳（会话级 6–10%）。
3. **跨负载不可比绝对值**：BM2 的 6 µs 与 cyclictest 的 5 µs 差 1 µs 属仪器差异（deadline 记账方式不同）。
4. **优先级不可跨 OS 对齐**：NuttX `PRIORITY=200` vs Linux FIFO 99，两侧各取"最高可用档"。
5. **测 BM2 必须关无线**（2026-10-22 新增）：SDIO 的 `irq 12` 落在被测核 CPU3。

### P4 — 先写"不能主张什么"，再写"主张什么"

已固化为 10 条清单（`RESULTS_ALL` §9 + `THESIS_MAINLINE` §4），例如：

- ❌ 不主张"内核化让抖动更小"（已证伪，见 §6.1）
- ❌ 不主张"cell 内 µs 级抖动是新发现"（Jailhouse 官方 gic-demo 就有 999 ns）
- ❌ 不声称击败 cRTOS（差别在"能否分解"，不在数字大小）
- ❌ 不把 BM2 的 3.3× 整体记成"隔离层收益"（内含 hypervisor 9 µs，见 §6.3）

> 这一条不是自我设限，而是 **把最容易被攻击的点提前变成"我们已经知道并量化了"**。

## 5. 数据链：从 268 到 4.9 是怎么串起来的

```
                       同一份编译器产物（不是三个程序）
                                  │
   ┌──────────────────────────────┼──────────────────────────────┐
   │                              │                              │
 [A 域] 普通 Linux           [B 域] Linux + 隔离           [C 域] NuttX 非根 cell
 268 µs (15 min)            7.834 µs (20 min)            4.9 µs (max 9, 1 h)
   │                              │                              │
   └────── 34× 隔离层 ────────────┴────── 1.6× 架构层 ──────────┘
                  （cgroup 分区 + IRQ/任务绑定 + 抢占抑制）  （硬分区 + 单核独占）
```

**编译器层**：A 域里 fused 与 native 的差 ≈ 0 → 这条链上编译器贡献为 0。

**第四层（2026-10-22 新增）**：把 C 域换回 Linux root cell，就得到
`裸 Linux 11 µs → root cell 20 µs`，即 **hypervisor 的确定性开销 ≈9 µs**。
于是"运行域"这一项也被拆成两段：**OS 唤醒路径** 与 **EL2 转发**。

> 这张图就是论文的核心图。它的价值不在于数字，而在于**每一段箭头都有独立实验支撑**。

## 6. 三个"反预期"结果——它们才是真正的卖点

### 6.1 编译器层贡献 ≈ 0（不是失败，是结论）

- 同编译器 A/B：cyclictest 0.2%、BM2 **+0.17%**（噪声级），指令 580 vs 580。
- 六个版本（gcc/clang × 过/不过 pass × 冻结/不冻结）**控制质量逐位相同**：
  `1.003868946 / -2.501873021 / 3.999878283`。

**怎么把它写成正面贡献**：不是"我们的 pass 不够好"，而是
> **在"抖动"这个量纲上，编译器没有作用面。**
> 抖动 = "什么时候被唤醒"（调度器/中断/hypervisor 决定）；
> 编译器改的是 "醒来后算多久"（exec）。
> 这两个量在本实验里**可以被证明是脱钩的**（下面 6.2）。

### 6.2 抖动与执行时间脱钩（最强的反证，两个独立方向）

| 方向 | 执行时间 | 抖动 |
|---|---|---|
| **T1 vs T2**（只冻结 `scan_cycle`） | 1.184 → 1.425 µs（**+20.4%**） | 直方图**逐桶相同**（6 µs×99 999, 7 µs×1） |
| **Linux vs NuttX**（同一源码跨域） | 1.16–1.24 vs 0.97–1.18（**≈1×**） | 20 vs 6 µs（**3.3×–18×**） |

一个"执行变慢 20% 抖动不变"，一个"执行一样抖动差十几倍"。
**两个方向相反、结论一致** → 这条结论关不掉。

### 6.3 那恒定 20 µs 是 hypervisor 的（今天定的因）

之前以为是"Linux 定时器精度/唤醒路径"。今天用 A/B/A 把它钉死在 hypervisor 上：

| 条件 | p50 | min | max | exec avg |
|---|---|---|---|---|
| HV 关（裸 Linux） | **11 / 11 µs** | 8–9 | 55 / 88 | 0.95–0.98 |
| HV 开（root cell） | **20 / 20 / 20 µs** | 15–16 | 101 / 127 / 137 | 1.18–1.25 |

- 三次重复**全部落在同一档** → 是**平台**（分布被整体平移），不是尾部抖动。
- 同一 hypervisor 下的 NuttX cell 只有 **6 µs** → **裸机 cell 不付这 9 µs**。
- 所以这 9 µs 是"**Linux 在 EL2 之下跑**"的代价，不是 hypervisor 的固有开销。

## 7. 与 cRTOS（Access'25）的关系：分栏，不击败

| | cRTOS | K-Fusion |
|---|---|---|
| 贡献类型 | 架构（Jailhouse + tRTOS 分区） | 架构 + 编译器 |
| 空载 jitter | min ~5 µs | 4.9 µs（同量级） |
| 带负载 max | NuttX ~60 µs / FreeRTOS ~20 µs | 五档已测（stream 档 p50 6.30） |
| 裸机对比 | 论文自认未做 | 埋点已留（未做） |
| **可分解性** | 单一产物 | **同一产物跨三域** |

**唯一的本质差别**：cRTOS 的 B 域与 C 域跑的不是同一个东西，所以它给不出"哪一层贡献多少"。

## 11. 一句话记忆

> 别人做的是"**把抖动压到 5 µs**"；
> 我们做的是"**把 268 → 7.8 → 4.9 这条线的每一段，用同一个二进制钉死归因**"。
> 前者是工程，后者是方法学。**后者才是这篇论文的贡献。**
