# C 组（手写硬中断读写）与 D 组（编译器生成）配对对照

日期：2026-11-18　平台：Pi4B / 5.15.49-rt47 PREEMPT_RT / 隔离核 CPU3 / HZ=1000

## 1. 这一轮补了什么

开题表 2 四组里，此前已落地 B（内核线程读写 = thread 臂）、D（编译器生成硬中断 = irq 臂），
A（用户态计算+读写）因需重构实验框架未做。本轮补上 **C 组：手写定时器硬中断读写**，
从而 B/C/D 三组齐备，可以做"手写 vs 生成"的配对对照。

- **源码**：`kfusion/src/kf_hand_let__手写硬中断读写.c`（489 行，独立手写，不经 Pass、不用 manifest）。
- **构建**：`kfusion/scripts/build_hand_module__编译手写中断模块.sh`（Pi 板编译，模块名 `kf_task.ko`）。
- **实验**：`kfusion/scripts/run_let_handwritten__C组手写中断实验.sh`。

## 2. 同源同任务 / 唯一变量

与 D 组严格配对，唯一变量 = **读写桩由谁产生**：

| 维度 | C 组（本轮） | D 组（irq 臂） | 是否一致 |
|---|---|---|---|
| 任务 | let_pc_shared 产消 | 同 | ✅ |
| 共享变量语义 | g_cmd/g_cmd_ver/g_cmd_snap | 同 | ✅ |
| 读/写相位 | 400µs 写 / 500µs 读 | 同 | ✅ |
| 逻辑时刻口径 | nominal = hrtimer 到期时刻，d=完成−逻辑，a=\|d\| | 同 | ✅ |
| 读写桩位置 | hrtimer 硬中断回调 | 同 | ✅ |
| 计算位置 | worker 线程（FIFO） | worker 线程（FIFO） | ✅ |
| ctx | 100% hardirq | 100% hardirq | ✅ |
| **读写桩来源** | **手写 C** | **PLCFusionPass 从契约生成** | **← 唯一变量** |

实现细节差异（诚实标注）：C 组 4 个相位（0/400/500/700µs）都在 hrtimer HARD 回调里编程，
D 组只有 400/500µs 两个 LET 相位走硬中断、0/700µs 的 group 相位走 worker 唤醒路径。
即 C 组硬中断里的 timer 编程频率约为 D 组 2 倍。这是实现差异，不是测量错误，
但意味着严格意义上 C/D 不是"仅读写桩一行不同"。

## 3. 数据（每轮 60s × 3 轮，同窗口）

正确性门禁全绿：三轮均 `skip=err=drops=hold=0`，`version_mismatch=0`，
`read_ok=write_ok≈60,980`，ctx 100% hardirq（仅个位样本 hardirq 与 softirq 交叠标记）。

每轮 `max|完成−逻辑|` 的中位数 / 极差（µs，读写分报，不报均值）：

| 组 | 读 中位 | 读 极差 | 写 中位 | 写 极差 |
|---|---:|---:|---:|---:|
| D 生成（irq 臂） | **4.1** | 0.04 | **6.1** | 4.55 |
| C 手写（本轮） | **8.1** | 4.11 | **9.7** | 3.87 |

三轮原始值（读/写 µs）：
- C：8.081/9.700、10.989/13.046、6.878/9.177
- D：4.078/6.088、4.071/9.907、4.107/5.361

## 4. 结论（按统计纪律收口）

1. **都能把抖动压到个位数微秒级**：C 与 D 的读写抖动都在 4–13 µs，比同窗口 B 组（内核线程）
   的 ~80 µs 低约一个量级。这再次支撑开题核心命题——把读写钉到硬中断能显著抑制抖动。
2. **C 组略高于 D 组（读 2×、写 1.6×），但不作优劣断言**：3 轮样本太小（符号检验 p=0.125 未达 0.05），
   且两组极差重叠（C 读极差 4.11 > C−D 中位差 4.0）。只能说"该条件下手写版读数偏高"。
3. **不把差异归因于"手写代码更差"**：C 组硬中断 timer 编程频率约为 D 组 2 倍（见 §2），
   这是更可能的混杂因素；要分离"桩来源"与"timer 编程频率"需要再做一个受控变体，本轮不做。
4. **组合意义**：至此 B/C/D 三组都有同窗口数据，开题表 2 只剩 A（用户态计算+读写）未落地。
