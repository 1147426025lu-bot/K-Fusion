# 中断影响评价：victim cyclictest 三条件对照

## 1. 目的与命题

开题的评价维度之一是把共享数据读写放进硬中断后，**是否抬高同核其他高优先级实时任务的延迟**。本实验用一个独立的 victim 任务直接测量这一外部性，而不是只看 LET 任务自身的读写抖动。

- 唯一变量：LET 模块状态 / 读写执行位置（baseline 无模块 / thread 读写在 FIFO80 RT 任务 / irq 读写在 hrtimer 硬中断）。
- victim：`cyclictest -a 3 -t1 -p 90 -i 1000`，绑隔离核 CPU3，优先级 90（**高于** LET 任务 80，故正常情况下不被其抢占），周期 1 ms。
- 每条件 60 s × 3 轮，6 万样本/轮；三条件窗口一致，可比。
- 平台：Pi4B / 5.15.49-rt47 PREEMPT_RT / `isolcpus=...,3` / realtime=1。

## 2. 上下文合法性核对（对照成立的前提）

| 臂 | hrtimer_hard | let_ctx_hardirq | let_ctx_task | 读抖动 max | 写抖动 max |
|---|---|---|---|---|---|
| thread | 0 | 0 | 2058 | 100.7 µs | 82.5 µs |
| irq | 1 | 2030 | 0 | 1.47 µs | 4.18 µs |

两臂执行位置完全分离（thread=task、irq=hardirq），无串扰。注意 victim 实验的 let 读写抖动与专项抖动实验数值不同（本实验 `let_log_cap=1000`、`REPS` 短、victim 与 LET 同核竞争），**两组数字不可跨实验比较**，各自只在其实验内成立。

## 3. 结果（每轮 victim 最大延迟，µs；统计量为中位数 + 极差，不报均值）

| 条件 | 3 轮 max | 中位数 | 极差 |
|---|---|---:|---:|
| baseline（无模块 / 底噪） | 55, 44, 35 | 44 | 20 |
| thread（读写在 RT 任务） | 33, 30, 23 | 30 | 10 |
| irq（读写在硬中断） | 33, 29, 46 | 33 | 17 |

图：`victim_cyclictest_compare.png`（中位数柱 + 每轮散点 + 极差线）。

## 4. 结论（按统计纪律收口）

1. **三条件 victim 最大延迟同量级（29–55 µs），未见硬中断读写对同核高优先级 victim 造成系统性延迟外溢。** irq 中位 33 µs 与 thread 30 µs 相差 3 µs，落在三条件的极差（10–20 µs）之内，不构成可分辨差异。
2. **不能反过来宣称"硬中断读写降低了 victim 延迟"。** baseline 反而是三者最高（中位 44 µs），且三轮单调下降（55→44→35），提示有跨轮漂移（CPU 空闲降频 / 温度 / 系统活动），baseline 与加载臂的比较受此混杂，不可做因果归因。
3. **irq 第三轮 46 µs 是异常拍**（另两轮 33/29），与 thread 的极值形态不同；单轮不可作结论，尾部形态需用更多轮/更长窗口确认。
4. 样本仅 3 轮：3 轮同向符号检验 p=0.125 > 0.05，即便出现一致方向也不足以支撑显著性断言。本次结论限于"该条件下未观察到外溢"，不作强弱量化。

## 5. 与开题命题的关系

- 本篇补齐了原缺口"中断影响评价"：此前只有 LET 自身读写抖动（internal），没有对外部 victim 的影响证据（external）。
- 组合结论：硬中断读写把**自身**读写抖动从 ~80–100 µs 压到 ~1.5–4.2 µs（thread→irq），同时**未观察到**对同核高优先级 victim 的延迟外溢——即"降抖动"在这套负载下没有以"抬高别人延迟"为代价。这是支持硬中断钉扎方案的关键平衡性证据。
- 边界：仅 CPU 空闲态、仅一类 victim（1 ms/优先级90）、3 轮。负载态、更长窗口、更多 victim 周期/优先级组合未做。
